1. What we collect

When you create an account, we collect:

  • Name and username — to identify your account
  • Email address — for account authentication and communication
  • Password — stored as a secure bcrypt hash, never in plain text
  • API key — generated automatically, used to authenticate API requests

When you use Roota to analyze logs, we store:

  • Log content — the text you paste or upload for analysis
  • AI diagnosis — the result Roota produces for each analysis
  • GitHub repository name — if you provide one (we never store GitHub credentials or tokens)
  • Feedback ratings — if you mark a diagnosis as correct or incorrect
  • Timestamps — when each analysis was performed

2. How we use it

We use the information we collect to:

  • Provide the service — authenticate you, run analyses, store your incident history
  • Improve diagnosis quality — feedback you provide (correct/incorrect) helps improve future analyses for your account over time
  • Communicate with you — if we need to reach you about your account or major service changes
  • Understand how the product is used — aggregate, anonymized usage patterns to guide development

We do not use your log data to train general AI models or share it with third parties for marketing purposes.

3. What we don't do

We will never:

  • Sell your data to advertisers, data brokers, or any third party
  • Share your log content with other users or organizations
  • Store your GitHub credentials — we access public repos via GitHub's public API only
  • Use your production logs to train AI models that are shared with other customers
  • Display advertising in any Roota product

4. Your log data

This is the most sensitive part and we take it seriously.

When you paste or upload a log file, that content is:

  • Sent to Google Gemini's API for AI analysis (subject to Google's data processing terms)
  • Stored in your incident history, associated only with your account
  • Never shared with other Roota users
  • Accessible only to you via your authenticated account

You can delete your account at any time to remove all stored incident data.

If your logs contain sensitive production data (credentials, PII, customer data), we strongly recommend redacting that information before analysis. Roota is not currently certified for handling regulated data (HIPAA, PCI-DSS, etc.).

5. Data storage and security

Your data is stored in a SQLite database on our server. We protect it by:

  • Hashing all passwords using bcrypt — we cannot recover your password if you forget it
  • Using API keys for all authenticated requests — never sending passwords over the wire after signup
  • Isolating user data — every database query filters by your user ID, so you can only access your own incidents

Roota is currently in beta. We are working toward more robust infrastructure and security certifications as the product matures.

6. Your rights

You have the right to:

  • Access your data — all your incident history is visible in your dashboard
  • Delete your account — email us and we will permanently delete your account and all associated data within 7 days
  • Correct your information — update your name and username in your profile settings
  • Change your password — available in your profile settings at any time

To request account deletion or a copy of your data, email us at the address below.

7. Third-party services

Roota uses the following third-party services that may process your data:

  • Google Gemini API — powers AI diagnosis. Log content is sent to Google's API for processing. See Google's terms.
  • GitHub API — used to fetch source code from repositories you specify. We access only public repositories and do not store GitHub credentials.

We do not use analytics platforms, advertising networks, or tracking cookies.
