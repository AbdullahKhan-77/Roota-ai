Getting started

Documentation

Roota is an AI-native production debugger that connects your crash logs to your actual source code and delivers exact root causes, timelines, and fixes — automatically.

ℹ️
Roota is currently in beta. The CLI, Python SDK, and C++ handler are fully functional. Web UI and API access require a free account.

Most debugging tools tell you what broke. Roota tells you why and how to fix it — by reading your actual codebase, not making generic guesses.

How it works

  1. Parses and structures all errors and warnings from your log
  2. Extracts which source files are mentioned in the crash
  3. Fetches the actual source code from your GitHub repository
  4. Sends logs + real source code to AI for grounded analysis
  5. Returns an exact diagnosis: root cause, timeline, cascading effects, and fix

CLI Overview

The Roota CLI is the fastest way to analyze a log file. It runs entirely on your machine.

python debugai.py [OPTIONS]

analyze command

# Basic analysis
python debugai.py --log crash.log

# With GitHub source code (recommended)
python debugai.py --log crash.log --repo owner/repo-name

# With C++ crash report
python debugai.py --log crash.log --repo owner/repo --crash-report crash_report.log

Options reference

OptionRequiredDescription
--logYesPath to log file. Supports any format.
--repoNoGitHub repo (owner/repo). Enables exact line-level diagnosis.
--crash-reportNoPath to C++ crash_report.log. Enables memory address resolution.
--versionNoShow current version.
--helpNoShow help and exit.

Python SDK

Automatically captures unhandled exceptions and sends them to your Roota server for analysis.

Setup

Copy debugai_sdk.py into your project, then add two lines:

import debugai_sdk

debugai_sdk.install(
    repo="owner/your-repo",
    server="http://127.0.0.1:8000"
)

How it works

The SDK installs a global exception handler using sys.excepthook. When any unhandled exception occurs:

  1. Full stack trace is captured automatically
  2. Formatted into Roota's log format
  3. Sent to your server's /ingest endpoint
  4. Server analyzes it and stores the incident
  5. Normal Python traceback still prints to terminal
✅
Works with any Python app — Django, Flask, FastAPI, scripts, or long-running services.

Configuration

ParameterDefaultDescription
repoNoneGitHub repo for source code fetching. Optional but recommended.
serverhttp://127.0.0.1:8000URL of your Roota server instance.

C++ Crash Handler

Header-only, binary-agnostic crash handler. Drop it into any C++ project — no build system changes required.

Setup

#include "debugai_handler.h"

int main() {
    debugai::install_crash_handler("logs/");
    // ... rest of your code
    return 0;
}

Compile with debug symbols

g++ -g your_app.cpp -o your_app
⚠️
The -g flag is required. Without debug symbols, memory addresses cannot be resolved to source lines.

What gets captured

BASE_MAP: 60b82188b000-60b82188d000 r--p 00000000 ... /path/to/binary
SIGNAL: 11
CRASH_ADDRESS: 0x60b82188d451

Analyze

python debugai.py --log service.log \
    --repo owner/repo \
    --crash-report logs/crash_report_20260615_143022.log
ℹ️
Requires WSL on Windows, or native Linux. Install addr2line with sudo apt install binutils.

POST /analyze

Analyzes a log file and returns an AI-powered diagnosis. Requires authentication.

POST http://127.0.0.1:8000/analyze
Content-Type: multipart/form-data
X-API-Key: your_api_key

log_file: <file>
repo: owner/repo-name  (optional)

Response

{
  "status": "success",
  "incident_id": 42,
  "stats": { "total_lines": 8, "errors": 5, "warnings": 2 },
  "diagnosis": "INCIDENT SUMMARY: ..."
}

POST /ingest

Receives crash data from SDKs. Used automatically by the Python SDK.

POST http://127.0.0.1:8000/ingest
Content-Type: application/json

{ "log_text": "...", "repo": "owner/repo", "source": "python_sdk" }

Log Formats

Two-stage parsing — regex first, AI fallback for everything else.

Stage 1 — Regex parser

2024-03-10 14:22:01 ERROR [UserService] KeyError: 9981

Stage 2 — AI parser

Handles Python tracebacks, JSON logs, Node.js, Java/Log4j, Nginx, and any custom format automatically.

GitHub Integration

Three-stage file disambiguation when multiple files share the same name:

  1. Filename match — find all files matching the name from the log
  2. Test file filter — prefer non-test paths
  3. Function verification — check which file actually contains the function from the traceback
ℹ️
Roota auto-detects your default branch — works with main, master, develop, or any branch name.

C++ Crash Analysis

Resolves raw memory addresses to exact source lines using addr2line.

  1. App crashes → signal handler captures BASE_MAP and CRASH_ADDRESS
  2. Roota calculates: file_offset = crash_address - base_address
  3. Runs: addr2line -e binary 0xoffset → file.cpp:line
  4. Fetches source from GitHub → 10/10 confidence diagnosis
⚠️
Requires binaries compiled with -g. Stripped binaries produce lower confidence diagnoses.
